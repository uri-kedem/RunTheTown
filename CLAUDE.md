# RunTheTown

A running app: the runner gives a start, a distance and a landscape, the app plans routes on
promenades, parks and quiet streets and guides the run by voice. One codebase, two shells:

- a static web app / PWA, served by GitHub Pages from the repository root (branch `main`);
- an iPhone app: the same web app inside a Capacitor 7 shell (`ios/`, bundle id
  `com.urikedem.runthetown`, iOS 15+, version 1.0 build 1), installed from Xcode.

The owner is Uri. He is not a programmer: explain in plain words, say what changed and what
he will notice, and give him complete commands to paste (never a command with a variable or a
path you have not verified). He decides product questions; you decide implementation.

Private notes that are not in git live in `docs/` on this Mac (the folder is gitignored):
`docs/mvp-status.md` (current state, history, what is unverified) and `docs/roadmap.md`
(the Nov 14, 2026 review: what to fix before the App Store, features ranked). Read both at the
start of a session, and keep `docs/mvp-status.md` up to date when something material changes.
`docs/RunTheTown-competitor-research-and-plan.docx` is private and must never be committed.

## Commands

```
npm test                                   # all Node test suites, about 12 minutes
node tests/test-navigation.mjs             # one suite (each tests/test-*.mjs runs alone)
python3 tests/ui/ui_nav.py                 # browser walk-through (needs: pip install playwright; playwright install chromium)
node build.mjs                             # build: bundle, version stamp, fingerprints, dist/
npm run ios                                # build + plugin patch + cap sync + open Xcode
node build.mjs && node native/patch-plugins.mjs && npx cap sync ios   # sync to Xcode without opening it
npm start                                  # local server on :8080 (python3 -m http.server)
```

Releasing the web app is `node build.mjs`, commit, push to `main` (Pages deploys it). The
phone gets a new version only through `npx cap sync ios` and Run in Xcode.

## How the build works (read before editing index.html or img/)

- The browser loads one classic script, `js/bundle.js`, generated by `build.mjs` from the ES
  modules in `js/` in a fixed order (the `ORDER` array). **Never edit `js/bundle.js`.** All
  modules share one scope in the bundle: a top-level name declared in two modules fails the
  build. A new module must be added to `ORDER`.
- The build stamps an 8-hex build number into `index.html` (`?v=` on the bundle, the styles and
  the manifest, and `#buildTag`) and into `sw.js` (`CACHE_VERSION`). Tell Uri the build number
  after a build; it is shown in the menu as "Version".
- Artwork is fingerprinted: `img/name.png|jpg|mp4|webm` is the source, the build writes
  `img/name.<hash>.<ext>`, rewrites every reference in `index.html`, `sw.js` and the manifest,
  and deletes the older fingerprinted copy. In source, reference either form; commit both the
  source and the fingerprinted file.
- `dist/` is what Capacitor packages; it is generated and gitignored.
- `node_modules` is not in git. `native/patch-plugins.mjs` re-applies our fix to the
  text-to-speech plugin (`native/ios-patches/TextToSpeech.swift`: the audio session is held
  only while a sentence is spoken, so music is lowered only then). It refuses to run if the
  plugin version is not the one the patch was written for.

## Product rules (Uri's standing decisions; do not change without asking him)

- Landscape first: if a park path, boardwalk or promenade can carry more than 60% of the run,
  offer only such routes. From an inland start, head for the sea or beach when it is in reach.
- Never route on a road without a sidewalk, except a short necessary crossing (capped at 10%
  of the run and 300 m + 2% of the distance).
- Quality over speed of planning. Laps at a track include the way there and back.
- In a small village with few roads, use the least significant ways.
- During a run: off route is a two-note chime and a quiet reroute, never "you're off route".
  A detour on the way out of an out-and-back changes the way home to match what was run. The
  route ending does not end the run: only End run (two taps) does, then Save / Delete.
  Splits say distance and pace only, never what is left. The journal shows the track actually run.
- Never touch the RTT head logo. Menu icons are hand-drawn white line art with the complete
  outlined runner (taken from `img/install-outline.png`), content in the 190x236 box at (10,10)
  of a 256 canvas. Ask before changing any icon.
- Cover page text is word for word from Uri's design. Do not rewrite it unasked.
- No data-clearance setting and no remembered running defaults: he rejected both.

## Conventions

- Plain JavaScript, no framework, no TypeScript, no bundler other than `build.mjs`. MapLibre GL
  5.24.1 and the Capacitor runtime are vendored in `js/vendor/`; the app must work with no CDN.
  The map is OpenFreeMap's vector tiles (styles `liberty` by day, `dark` at night); the app
  never talks to MapLibre directly, only through `js/glmap.js`.
- Comments explain why, in full sentences, above the code they describe. Match the style around.
- Every behaviour change gets a test in the matching `tests/test-*.mjs`; the navigation suite
  drives a `Navigator` with a `SimulatedRun`, the planner suites plan in the synthetic city.
- After editing anything the page loads, run `node build.mjs` and the relevant suites before
  telling Uri it is done. For anything on the run screen also run `tests/ui/ui_nav.py`.
- The test browser has no H.264: the cover clip plays there from the `.webm` copy.
- Xcode log lines that are normal and need no fix: the UIScene notice, "Could not create a
  sandbox extension", MobileAsset voice queries failing with 2, the keyboard toolbar's
  "Unable to simultaneously satisfy constraints", RTIInputSystemClient, debugger hangs.
